# Group-Level Software Evidence Check v1.0（集团层面软件证据核查）

> 状态：2026-09-27 用户评审确认，强制生效（工业 v4.1 与市政 v3.4.x 共用）
> 适用范围：工业雷达 `daily signals`、市政雷达 `opportunities[]` 与 `background_monitoring[]` 全部线索

## 背景

2026-09-27 用户评审石墩子山水厂线索（OPS-20260925-WLMQ-001）时指出：线索只体现了"水质仪表采购需求"，**看不出与 iMS 软件的直接或间接联系**。用户明确期望的线索丰富方式是——**先查清线索主体所属集团/母公司在软件方面做过哪些公开工作（平台建设、软件采购、自研软著/专利、公开发表、试点尝试等），用集团层面的公开事实支撑 iMS 关联判断**，而不是只停留在"项目需要仪表 → iMS 可建立"的泛化推理。

本规范将这一口径固化，作为所有线索证据补充的执行基准。

## 核心规则

### 1. 每条线索必须补充"集团层面软件公开证据核查"

无论线索处于哪个阶段、得分高低，发布前必须完成：

- **group_entity（集团/母公司主体识别）**：确认线索主体所属集团/母公司，含重组历史、股权关系、下属科技/信息化子公司（如"乌鲁木齐水业集团 → 2023-11-22 整合为水投集团；全资科技子公司科信公司"）。
- **group_software_facts（集团软件公开工作——FACT）**：仅收录公开来源明确说明的事实，逐条带来源：
  - 软件平台建设/采购/运维（智慧水务平台、数据中台、调度系统、远控系统、SCADA 等）；
  - 集团层面软件招标/中标记录（含金额、供应商）；
  - 自研软件著作权/专利；
  - 公开发表的技术文章、论文、行业交流材料、官网新闻；
  - 试点尝试（远传水表、无人水厂、AI 监测、漏损 DMA、黑灯实验室等）；
  - 政府/行业对集团数字化的公开定调（如领导调研提出"数字化/无人化转型"）。
- **group_software_inferences（由集团事实推出的判断——INFERENCE）**：如"集团已建智慧水务平台+智能远控系统 → 改扩建新增仪表数据必然接入集团平台体系 → 需要仪表数据底座（多品牌/多站点数据质量与健康管理）→ iMS 位于'仪表与集团平台之间'的数据质量层"。
- **group_software_unknowns（公开检索不到——UNKNOWN）**：如实列出待验证问题（平台架构是否兼容第三方仪表数据、现有仪表品牌/数量/联网状态、软著具体内容等），**禁止编造，禁止用万能套话填充**。
- **ims_link_strength（iMS 关联强度）**：三档单选——
  - `DIRECT`：集团公开信息存在与仪表数据管理/软件平台直接相关的采购或建设信号；
  - `INDIRECT`：集团有明确数字化/软件动作，但与 iMS 的关联需推断建立；
  - `NO_EVIDENCE`：公开检索无集团软件工作证据，如实标注并给出下一步验证路径。
- **evidence_sources**：该条集团证据的公开来源 URL + 发布时间/发布方；`checked_at` 记录核查日期。

### 2. 分级标注纪律

沿用既有纪律：`FACT`=公开来源明确说明；`INFERENCE`=由事实推出的合理判断；`UNKNOWN`=无法验证。**UNKNOWN 允许如实标注，但字段不得缺失**；不得把 INFERENCE 写成 FACT，不得把"无法验证"美化成"已验证"。

### 3. 下游使用

集团软件证据必须回写到三处：

- **Qualification Card**：作为 iMS 论证的实证层（FACT/INFERENCE/UNKNOWN 并列呈现），替换单一"项目需要仪表"式推理；
- **action_triad.find_who**：新增集团信息化/数字化部门、科技子公司（如科信公司）作为接口人；
- **to_verify.ims**：把 group_software_unknowns 纳入待验证问题，交给 Company Agent。

## 参照样本（2026-09-27 用户认可）

**乌鲁木齐石墩子山水厂改扩建（OPS-20260925-WLMQ-001）**：

- group_entity：乌鲁木齐水业投资发展集团有限公司（2023-11-22 由水业集团与昆仑环保整合，市国资委监管，注册资本 100 亿；全资科技子公司：乌鲁木齐水业科技信息技术有限公司）
- group_software_facts：
  - 原水业集团已有《智慧水务平台》，2024-06 用友网络中标本平台在水投集团全级次运维覆盖及服务升级（成交 175 万元）；
  - 2026-06 智慧水务-供水管网模型体系项目招标：覆盖全集团供水管线，六大核心场景（管网压力管理/运行管理/DMA 漏损管控/应急处置/科学调度/水质管理），二标段减压阀自动化升级统一接入集团智能远控系统；
  - 科信公司：19 项软件著作权、与川力智能联合申请管网流量监测专利（2026-09 授权）、2020 年在新装水表上加装远传设备（数字化第一步）、完成 7 水厂 73 点位视频监控接入；
  - 市委副书记 2024-06 调研石墩子山水厂，明确要求"水厂向数字化、无人化转型升级"（水协官网）；
  - 集团官网"四化一体"含"智慧水务一体化"。
- group_software_inferences：集团已建平台+远控体系 → 改扩建新增仪表数据必然接入集团平台 → 仪表数据底座（多品牌/多站点数据质量与健康管理）成为平台之下的空白层 → iMS 机会点成立（仪表先行 + 数据底座跟进）。
- group_software_unknowns：集团平台底层架构是否兼容第三方仪表数据接入；石墩子现有仪表品牌/数量/联网状态；科信公司软著具体内容；集团是否已有同类仪器管理软件。
- ims_link_strength：`INDIRECT`（集团数字化动作明确，iMS 直接采购信号无公开证据）。

## 执行时序（并入现有流水线）

- **工业雷达**：Stage 2 Qualification 的 PULL 四维与 Evidence 之后，追加本核查；Stage 3 富化时补充集团证据来源。写入 daily JSON 每条信号，并同步 latest.json 聚合。
- **市政雷达**：Stage 3 Enrichment 的 customer_background 之后，追加本核查；写入 opportunities[] 与 background_monitoring[] 每条，并同步 latest.json。
- **发布前校验**：`Quality Control Before Publish` 增加一条——每条线索必须含 `group_software_evidence` 且 `ims_link_strength` 非空；缺失视为任务未完成。
