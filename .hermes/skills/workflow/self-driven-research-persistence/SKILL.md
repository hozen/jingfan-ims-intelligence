# 自驱动研究任务持续化工作流

## 核心问题

自驱动研究任务（crowd-driven）需要在多次会话间持续工作。每次醒来时，agent必须能从上次的进度继续，而不是重新开始。

## 解决方案：WORKLOG.md

每个work项目根目录必须有 `WORKLOG.md`，记录每一步操作和状态。

## WORKLOG.md 标准格式

```markdown
# work-XX 项目名称 - 工作日志

**版本：v1.0**
**创建：YYYY-MM-DD**
**最后更新：YYYY-MM-DD**

---

## 一、项目目标（来自PROJECT.md）

[简要描述研究目标]

---

## 二、工作日志

### Step 01 — 操作名称（YYYY-MM-DD）

**操作**：具体做了什么
**完成状态**：
- [x] 已完成项A
- [x] 已完成项B
- [ ] 待完成项C

**下一步**：接下来要做什么

---

### Step 02 — 操作名称（YYYY-MM-DD）

[同上格式]

---

## 三、关键反思（每季度必答）

1. **当季最大异常是什么？是真实信号还是统计扭曲？**
   → 回答

2. **哪些持仓/判断获得了支持/挑战？**
   → 回答

3. **如果只能给决策者一句话，本季度最重要洞察是什么？**
   → 回答

4. **如果错了，会怎么错？（预设证伪条件）**
   → 回答

---

## 四、下一轮工作清单

- [ ] 待办项A
- [ ] 待办项B
```

## 配套文件

每个work项目还需要：

| 文件 | 作用 |
|------|------|
| `PROJECT.md` | 原始提示词存档——保存用户最初的需求描述 |
| `WORKLOG.md` | 每步操作记录——可接续 |
| `index.html` | wiki主索引页 |

## 会话恢复流程

1. 读取 `WORKLOG.md`
2. 找到"下一步"清单
3. 继续执行
4. 完成后更新WORKLOG
5. 更新 work-board.txt 中的进度

## 关键原则

1. **每步必记**：即使是小小的进展也要记录
2. **下一步必列**：每次结束前明确下一步是什么
3. **状态标注**：用 `[x]` 标记已完成，`[ ]` 标记待完成
4. **进度同步**：每次会话结束前更新 work-board.txt
5. **数据不造假**：数据缺失时明确标注"数据待补"

## 与 PROJECT.md 的区别

- `PROJECT.md`：用户的原始需求，不常修改
- `WORKLOG.md`：我的操作记录，每次会话更新

## 适用场景

- 自驱动研究任务（crowd-driven）
- 任何需要多次会话完成的研究项目
- 并行多任务研究（每个任务有独立的WORKLOG）
