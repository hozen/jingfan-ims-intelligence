# GTM + IMS白区激活工具包

## 背景
IMS（设备智能运维软件）应定位为"设备科工具"而非"信息化平台"。设备科有需求/预算/权力自行决定购买，IT部门是Technical Gatekeeper，平台定位会触发IT拦截导致死局。

## GTM框架（完整版）

### 1. DMU采购决策单元
| 角色 | 通俗说法 | IMS场景 |
|------|---------|---------|
| User | 用工具干活的人 | 设备科工程师 |
| Technical Gatekeeper | 技术有一票否决 | IT/信息化部门（⚠️拦截者）|
| Financial Gatekeeper | 预算有一票否决 | 财务或厂长 |
| Decision Maker | 最终签字人 | 小额=设备科 / 大额=副总 |
| Champion | 内部帮你推的人 | 关键盟友 |
| Blocker | 内部挡你的人 | IT部门（当平台定位时）|

### 2. 三种进入策略
- **策略A 设备科直销**：定位=设备科智能运维工具，设备科自己提需求自己审批。适合新机捆绑/巡检续约/年度框架客户。最快路径。
- **策略B Champion推动**：找到内部抱怨最多的人，给他工具让他内部推。适合已有运维合同要上大项目。最稳路径。
- **策略C 竞品窗口**：竞品合同到期/出问题，主动出击。最好时机。

### 3. Customer Journey七阶段
```
Awareness → Consideration → Evaluation → Decision → Installation → Adoption → Renewal
```

### 4. 核心原则
> 不要正面进IT的门。绕道设备科，让设备科主动提出需求，内部政治比外部推销有效10倍。

## 目标交付物
设备科切入工具包（不是PPT）：
- 一页价值主张（对照设备科KPI：在线率/数据准确/运维成本）
- 价格锚点（IMS占仪表采购的百分比，让设备科觉得便宜）
- 竞品对比表（设备科视角）

## 使用场景
Work-04 IMS白区激活分析。用GTM框架拆解每个真实案例：谁是你的Champion，谁是你的Blocker，卡在Customer Journey哪一步。
