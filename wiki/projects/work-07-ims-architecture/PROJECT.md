## 1. 研究背景与动机

水协2026年会最大竞争信号：**上海三高**展示"智慧水务管控平台 + AI大模型解决方案"。

## 4. 技术可行性评估

### 4.1 边缘小模型

| 模型 | 量化 | 内存占用 | 适用场景 |
|------|------|---------|---------|
| Qwen-7B | INT4 | ~4GB | 标准工控机（8GB RAM可用） |
| Qwen-1.8B | INT4 | ~1GB | 低配设备 |
| Phi-3-mini | INT4 | ~1.8GB | 极致边缘 |

**结论：工控机跑小模型完全可行**，不是技术瓶颈。

### 4.2 开源框架参考

| 框架 | 来源 | 相关度 | 备注 |
|------|------|--------|------|
| **IoT-Edge-MCP-Server** | poly-mcp, 23★ | ⭐⭐⭐⭐⭐ | SCADA/PLC/MQTT/Modbus → MCP协议，MIT |
| **EdgeAI-MCP** | xiao98 | ⭐⭐⭐⭐ | 任意AI模型读取工业设备数据 |
| **IMCP** | arkCyber | ⭐⭐⭐⭐ | 工业安全增强版MCP |
| **LLM4ICS** | dontcallmeAJ | ⭐⭐⭐⭐ | 多供应商PLC/SCADA + LLM，MIT |

**结论：MCP协议是工业数据接入AI的事实标准**，国内水务行业尚无先例但框架已ready。

### 4.3 推荐技术路线

**MCP套壳路线**（快，比自建省6-12个月）：
```
传感器/PLC/SCADA → MCP Server → 本地Qwen-7B INT4 → JSON结构化报告 → 微信/Dashboard推送
```

vs

**LangGraph自建路线**（慢，完全从头）：
```
自建Agent框架 → 接入IMS数据库 → 定制化开发 → 维护成本高
```

## 5. Hach IMS的差异化优势

| 资产 | 说明 | Agent价值 |
|------|------|---------|
| 仪表故障知识库 | 10+年Hach仪表异常诊断经验 | 根因分析能力，通用SCADA没有 |
| 工艺参数经验值 | 氨氮/总氮/溶解氧/ORP最优区间 | 告诉客户该怎么调，不是只展示数据 |
| NT6800/LDO II/NH6000sc | Hach自有仪表生态 | Agent的感知层，竞品无法接入 |

**核心差异化**：不是"能接入AI"，而是"有10年积累的水务工艺知识"。

---

## 6. 推荐架构（四层）

```
┌─────────────────────────────────────────────────────────┐
│ 边缘设备层  传感器/PLC/SCADA/本地数据库                   │
│            ↓                                             │
│ AI推理层    MCP Server + Qwen-7B INT4（本地）→ JSON输出   │
│            ↓                                             │
│ 异步报告层  定时报告 / 异常告警触发 / API-Webhook集成      │
│            ↓                                             │
│ 客户端层    微信企微推送 / Dashboard / 移动App / API对接   │
└─────────────────────────────────────────────────────────┘

核心卖点：数据不出厂 | 本地LLM推理 | 零运维 | 快速上线
```
