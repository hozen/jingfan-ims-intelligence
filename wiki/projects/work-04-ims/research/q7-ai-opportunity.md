## 一、IMS的现实约束

| 约束 | 说明 | 影响 |
|------|------|------|
| 数据不出厂 | 水务公司数据敏感，不能上云 | 只能做本地/边缘AI |
| 工控机性能 | 8GB RAM，无GPU | 只能用小模型（7B以下） |
| 客户预算 | SaaS年费制，无AI预算 | 不能收额外AI费用 |
| 竞品压力 | 上海三高已有"AI大模型"概念 | 需要回应 |

**结论**：IMS的AI必须是**轻量、本地、无额外成本**的方案。

## 二、AI落地方向筛选

### 方向A：智能告警（优先级最高⭐⭐⭐⭐⭐）
- **现状**：IMS只做阈值告警（>报警值→发短信）
- **AI价值**：根因分析——"为什么报警？可能是什么故障？"
- **数据需求**：仪表故障知识库（已有10年积累）
- **落地难度**：⭐（知识库+RAG即可）

### 方向B：工艺优化建议
- **现状**：展示实时数据，告诉客户"氨氮高了"
- **AI价值**：告诉客户"氨氮高了→可能是xxx→建议调xxx"
- **数据需求**：工艺参数经验值（已积累）
- **落地难度**：⭐⭐（需要验证知识库完整性）

### 方向C：报表自动生成
- **现状**：客户手动填日报/月报
- **AI价值**：自动生成报告+解读
- **数据需求**：报表模板+历史数据
- **落地难度**：⭐⭐（实现简单，价值一般）

### 方向D：智能问答
- **现状**：客户打电话问技术支持
- **AI价值**：文档问答+故障自诊
- **数据需求**：产品手册+知识库
- **落地难度**：⭐⭐⭐

## 三、推荐落地方案：智能告警助手

```
传感器/PLC → IMS数据库 → MCP Server → 本地小模型 → 告警根因分析 → 微信推送
```

**核心卖点**：
1. 数据不出厂（本地部署）
2. 利用已有知识库（差异化）
3. 不增加硬件（工控机够用）
4. 快速上线（3个月）
