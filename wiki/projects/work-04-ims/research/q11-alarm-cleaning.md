## 二、行业最佳实践：报警数据清洗策略

> ⚠️ **研究受限**：本服务器外网访问受限，以下内容基于行业通用方法论整理，待网络恢复后补充具体文献来源。

### 2.1 报警过滤层级体系（ISA-18.2 / IEC 62682）

| 层级 | 策略 | 说明 |
|------|------|------|
| **抑制层（Suppression）** | 维护模式屏蔽、条件抑制 | 设备在服务/校准时，屏蔽关联报警 |
| **去重层（Deduplication）** | 时间窗口去重、首位报警保留 | 同设备同因，N分钟内只保留第一条 |
| **限制层（Rate Limiting）** | 频率限制、振铃抑制 | 同一设备报警频率>阈值，触发通信故障判断 |
| **标识层（Classification）** | 瞬时自恢复标注、真实故障分级 | 自动关闭的报警标记为"瞬时/疑似噪声" |
| **延迟层（Delay）** | 确认延迟、滤波延迟 | 短时瞬变不触发真实报警 |

### 2.2 MMS数据清洗框架

```
原始数据流
    │
    ▼
[Step 1] 设备状态关联合并
    │ 设备服务模式标志 → 屏蔽所有工艺报警
    │ 网关在线状态 → 离线期间屏蔽离线报警
    ▼
[Step 2] 时间窗口去重（可配置窗口：默认5分钟）
    │ 同一设备 + 同一报警类型 → 时间窗口内只保留第一条
    ▼
[Step 3] 频率过滤
    │ 同一设备同因报警 > 10次/小时 → 判定为"通信故障"，抑制后续
    ▼
[Step 4] 瞬时自恢复检测
    │ 报警从发生→恢复 < 5分钟，且无需人工处理 → 标记为"瞬时报警"
    ▼
[Step 5] 有效报警输出
    │ 有效报警进入统计报表
    │ 瞬时报警进入日志存档（不计入KPI）
```

### 2.3 关键判断参数

| 参数 | 推荐值 | 说明 |
|------|-------|------|
| 去重时间窗口 | 5 min | 可按报警类型分层配置 |
| 频率阈值 | 10次/小时 | 超过视为通信故障 |
| 瞬时自恢复阈值 | 5 min | <5min自动恢复判定为瞬时噪声 |
| 维护屏蔽延迟 | 上下电后3分钟 | 防止开关机噪声 |

## 三、MMS应用建议

### 3.1 当前MMS数据质量痛点

- MMS作为平台聚合层，接收来自不同IMS站点的数据
- 各站点的"瞬时报警"会传导至MMS，导致统计数据失真
- 网关/设备闪断产生的报警不反映真实设备状态，但占用报警处理资源

### 3.2 MMS数据清洗方案

**在MMS侧实施与IMS一致的清洗逻辑**：

1. **接收端打标**：IMS上行数据携带设备状态标志（在线/服务模式/通信故障）
2. **MMS聚合层实施去重**：时间窗口内同设备同类型数据点只保留第一条
3. **频率检测**：MMS统计各设备单位时间内数据上报频率，频率异常触发告警
4. **噪声标签**：被判定为瞬时报警的数据不进入KPI计算，但保留原始日志

### 3.3 实施优先级

| 优先级 | 措施 | 难度 |
|--------|------|------|
| P0 | 设备服务模式与报警屏蔽关联 | 低 |
| P0 | 网关离线期间离线报警不计入有效报警 | 低 |
| P1 | 时间窗口去重（5min窗口） | 中 |
| P1 | 频率过滤（>10次/小时判定为通信故障） | 中 |
| P2 | 瞬时自恢复自动标注 | 高（需历史数据积累） |
